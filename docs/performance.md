# 桌面性能优化记录（2026-10-21）

## 原因与改动

原首页把全部作品的详情字段传入客户端，并为折叠的祭典生成全部作品表格。线上桌面检查在零展开状态下记录到 90,451 个 DOM 节点、4,373 行作品表格、3,150 个图片元素。

- 首页只传列表需要的字段；详情入口可用状态仍由原 `hasWorkDetail` 规则在服务端计算。
- 折叠祭典不生成表格和图标，展开后才生成。
- 搜索只自动展开第一个匹配祭典，其他命中祭典显示数量并可手动展开。搜索结果每个祭典先显示 50 条，可继续分批显示；换词重置数量。
- 搜索计算延后到输入更新之后执行。
- 作品详情侧栏只接收编号、题名和入口状态，不再携带整场祭典的详情。
- 目录和视图切换链接关闭自动预取，点击时加载目标页面。

## 核验范围

全量比对 78 个祭典、4,373 条作品的列表字段、下载链接和详情入口状态，结果一致；详情正文、来源与截图仅从列表传输中移除，归档数据保留。

桌面检查涵盖祭典展开／收起、hash 定位、搜索及清空搜索、详情导航、截图加载、素材祭表格和规则显示、整理版切到原貌版。广泛命中的搜索另检查按需展开与分批显示。

使用“2000”搜索命中 60 个祭典、2,496 条作品；初次只展开第一个祭典，生成 21 行。手动展开 2014 红白后显示 50 / 100 条，点击“显示更多”后完整显示 100 条。

部署继续使用纯 Workers Static Assets，不引入服务端脚本或动态数据接口。

## 原貌版图片加载（2026-10-21）

检查 4,569 个原貌 HTML 页面。发现多个目录和截图长页一次加载全部图片；还有以 CSS 背景展示作品截图的目录。

`npm run build` 的 `postbuild` 阶段只优化 `out/original-pages` 发布副本，保留 `public/` 和 `catch/` 的恢复证据及全部原始图片：

- 每页前两张非内嵌图片不新增延迟加载设置；其余本地大图片（至少 16 KiB）补充原生 `loading="lazy"`。小图标保留立即加载，避免未指定尺寸的图标框暂时缩小。
- 未明确指定解码方式的图片补充 `decoding="async"`；已有加载设置、高优先级图片和图像映射保留原行为。
- 为使用 `.entry-card` 的固定尺寸目录卡片延迟加载较大背景截图，接近视区 300 px 时恢复原背景。保留前两张、无 IntersectionObserver 的立即加载回退，以及无 JavaScript 时的 CSS 回退。
- 不压缩、缩放、转码图片，不更改原链接、悬停处理或原貌 CSS 排版。

桌面本地静态服务使用 `no-store`，记录打开页面后、滚动前服务器实际收到的图片请求；包括 CSS 背景，重复 URL 由浏览器合并。浏览器视口为 1280 × 720，以下不是公网耗时测试。

| 页面 | 原图片请求量 | 优化后首批图片请求量 |
| --- | ---: | ---: |
| 2020 红白目录 | 16,614,840 B / 109 请求 | 12,288,195 B / 95 请求 |
| 2014 红白 `hyou2.html` | 13,376,590 B / 89 请求 | 459,187 B / 12 请求 |
| 2022 红白背景截图目录 | 7,909,215 B / 103 请求 | 1,081,511 B / 65 请求 |

2020 目录全部 143 个图片框的位置和尺寸与基准一致；2014 截图页总高度保持 103,905 px，首屏图片及滚到页尾后的图片均加载；2022 目录的 72 张卡片位置、尺寸、链接与基准一致。背景加载也在原貌版的 sandbox iframe 中检查，首屏无待加载卡片。

临时全量结构比对覆盖 4,569 页、18,639 个图片元素和 47 个延迟背景：撤销加载属性与背景加载代码后，其余 DOM、内容、链接和事件属性与原副本一致。浏览器原生延迟加载会预取视区附近图片，实际请求量随视口及浏览器策略变化。

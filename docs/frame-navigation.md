# 原貌版框架导航修复

原貌版外层使用 `sandbox="allow-scripts"`。旧站的命名框架链接不能直接导航兄弟框架，`_top` 也不能导航外层应用。2009 红白包含 `menu → main`、`title → ss` 两套框架，原来的单菜单适配没有覆盖。

`scripts/recover-frame-navigation.ts` 提供生成器共用的导航转换，同时可离线更新已有展示副本：

```powershell
npx tsx scripts/recover-frame-navigation.ts
```

转换保留 HTML 排版及沙箱权限，增加祭典内的经典脚本。链接向父框架发送消息，原貌根框架按名称向下分发；`_top` 限定在原貌根，`_parent` 由直接父框架执行。消息必须来自实际子框架或向下分发的直接父框架，URL 必须属于同源、同祭典的已归档 HTML 清单。查询参数和锚点保留。外部链接、下载、新窗口及带修饰键的点击不纳入转发。

2020 GW 保留专用动态脚本适配。已有菜单适配保留；新脚本在捕获阶段处理本地导航并停止旧点击处理，避免同一次点击重复转发。原始来源缓存不修改。

本批修改文件见 `catch/frame-navigation-repair.json`；各祭典 `original-view.json` 登记新增脚本和兼容修改。此批属于共用导航修复，不代表各祭典内容验收完成。

2026-10-22 临时内存检查覆盖兄弟框架、嵌套目标、原貌根切换、父框架切换、缺失页面、外站 URL、伪造消息以及原生自身／新窗口／修饰键行为。未进行浏览器交互，桌面验收仍为 pending。待验收链路包括 2009 红白首页菜单 → 作品一覧 → 具体作品 → 返回首页，以及已有嵌套框架和动态适配祭典的回归。

## 共用侧栏与原貌浏览器外框（2026-10-23）

整理版首页与原貌版共用 `src/components/festival-sidebar.tsx`。侧栏顶部切换当前祭典的两种视图；在原貌版中选择其他祭典时继续打开其原貌版，未收录原貌版的祭典回到整理版。目录会定位当前祭典，沿用固定桌面宽度布局。

`src/components/original-festival-view.tsx` 在沙箱外统一提供 IE6 风格窗口、后退、前进、刷新、主页、原站地址与复制按钮。窗口上方不再重复显示祭典标题和说明，标题栏只显示祭典名，不附加浏览器品牌文字；保留窗口内原有的 e 图标。站点 favicon 复用 VIPRPG-ZH-Archive 的 `public/icon/windI.png`，站点标题旁不增加图标。地址可以直接选中；剪贴板不可用时提示手动复制。外框记录原貌根页面与各层子框架的 URL，后退／前进和刷新重新加载并恢复该框架树，不调用外层浏览器的 `history.back()`。框架中的普通链接、命名框架适配和 2020 GW 专用适配仍由原有脚本处理。

`public/archive-browser.js` 只在原貌页内运行，逐层转发实际子框架的状态，恢复指令只接受直接父窗口；外框还检查当前 iframe、祭典路径及已登记 HTML 清单。沙箱权限仍为 `allow-scripts`。脚本在加载与查询时报告状态，以覆盖页面先于 React 初始化完成的情况；也同步锚点及 History API 的地址变化，保留 `replaceState` 的替换语义。

Cloudflare 静态托管会把 `.html` 跳转到无扩展名地址，把 `index.html` 跳转到目录地址。外框将这些地址按已登记页面清单归一化后再保存和恢复，查询参数与锚点照常保留，不把未登记的路径当作可导航页面。

本地 HTTP 服务模拟上述真实重定向及不带 charset 的响应头后，2014 GW 普通详情的后退／前进／刷新、2008 红白三层框架的详情与返回、2020 GW 带查询参数的动态页面与返回均已验证。

已有展示副本可离线接入，不访问源站、不改写来源缓存：

```powershell
npx tsx scripts/recover-original-browser.ts
```

该步骤为 78 个原貌版的 4,569 个 HTML 插入共享脚本引用，并生成 `src/data/original-page-sources.json`。地址映射复用恢复配置、`recovery.json` 的 `originalResources` 和种子 URL；普通路径按原站基址还原，2012 红白的静态 CGI 副本还原为对应查询地址。2020 GW 的归档提示页使用站点地址或已记录的外链，不虚构原站同名页面。共用恢复脚本和 2015 夏之阵专用恢复脚本均已接入此步骤，避免再次恢复时丢失控制功能。

临时内存检查覆盖框架状态更新、嵌套消息转发与恢复、跨祭典／外站／伪造消息拒绝和地址查询参数保留。本次属于共用页面结构调整，不更新祭典内容完成状态。

经用户授权，桌面浏览器已验证以下链路：

- 2009 红白：菜单切换普通页面、进入另一组 frameset、选择详情，后退／前进、刷新、主页及再次后退均恢复对应页面，外层保存库路由保持正确。
- 2008 红白：三层框架中的目录链接更新目标框架；后退／前进和刷新恢复目标框架及各层目录。
- 2020 GW：带 `page` 参数的根页面与动态子框架整体后退／前进、刷新；一次操作中的自动跳转合并为一条历史记录，不暴露初始化中间页。
- 2017 红白：原站 `pushState` 从 `id=1` 切换至 `id=2`，地址栏同步，后退／前进、刷新保留查询参数。
- 侧栏切换整理版／原貌版、定位并展开对应祭典、在原貌版侧栏选择其他祭典；复制地址实际读回一致，剪贴板拒绝时选中完整地址并提示手动复制。
- 1440×1000 与 1280×900 桌面布局检查；外框截图位于本地 `test-results/original-browser-1440.png`、`test-results/original-browser-1280.png`，原貌内容已遮盖。沿用原有 1280px 最小桌面宽度，1280px 窗口带系统滚动条时仍可能出现小幅横向滚动。

浏览器检查发现并修复了 iframe 先于 React 初始化完成时漏收 `load`、导致导航按钮持续禁用的问题：状态查询现在同时报告文档完成状态，已有加载完成的 frame 也能正确启用按钮。上述链路没有浏览器 console 错误；其余祭典未逐一做交互验收，图片／内容完整性与生产部署不属于本次验收结论。

## 原貌页编码声明修复（2026-10-23）

全库 4,569 个 HTML 的字节均为有效 UTF-8。初次检查发现 2014 GW 的 69 个详情页缺少 HTML 编码声明，其他页面未发现缺失、冲突或声明超出首 1,024 字节的问题。线上只读检查 `https://fes.viprpg.org/original-pages/2014-gw/entry/001.html` 最终跳转到 `/entry/001`，返回 `Content-Type: text/html`，正文是 UTF-8 且没有编码声明。按该响应条件复现时浏览器选择了 GBK，详情 No.001 出现 11 个替换字符。

离线整理脚本已为这 69 页补上靠前的 `<meta charset="UTF-8">`，清单见 `catch/original-browser-encoding-repair.json`；来源缓存不改写。共用接入步骤检查读取副本的实际 UTF-8 字节，并将缺失、冲突或过晚的编码声明统一放在页面头部，避免重建后复发。

通过真实本地 HTTP 转发服务去掉响应 charset 后，No.001 与 No.069 均以 UTF-8 解码且没有替换字符；No.001 的后退／前进和刷新仍正常。此检查不依赖开发服务器自动附加的 UTF-8 响应头。最终外框预览保存在本地 `test-results/original-browser-final-1440.png`（原貌内容遮盖）；线上未部署。

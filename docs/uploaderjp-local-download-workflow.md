# uploader.jp 本地下载工作流

本工作流将 VIPRPG 文件保存到本机，提供自动队列、实时进度窗口和独立前台告警。当前阶段只下载到本地，不调用百度上传，也不自动删除已保存文件。

**启动与控制**

在本仓库目录运行：

```powershell
# 初始化或继续下载，同时打开实时进度窗口
pwsh -NoProfile -File scripts/Invoke-UploaderRescue.ps1 -Action Start

# 查看机器可读的当前状态
pwsh -NoProfile -File scripts/Invoke-UploaderRescue.ps1 -Action Status

# 请求安全暂停，保留完整文件、下载断点和队列
pwsh -NoProfile -File scripts/Invoke-UploaderRescue.ps1 -Action Pause

# 关闭进度窗口后，可重新打开；此命令本身不启动下载
pwsh -NoProfile -File scripts/Invoke-UploaderRescue.ps1 -Action Monitor
```

进度窗口包含总完成数、当前候选数、连续成功数、真正错误数、自动重试次数和已恢复项数、保存容量、磁盘空闲、当前文件进度与速度，并提供“暂停并保留断点”“继续下载”“打开保存目录”“打开日志”按钮。每秒更新。关闭窗口不会停止后台下载或独立告警。

暂停为协作式操作：检查停止标记后保留现场。网络读取阻塞时可能需要等到本次读取超时，不能在状态尚未变为 `paused`、原进程句柄仍存活时重复启动。再次 Start 会从既有 SQLite 队列继续，已完成文件不重下。真正错误导致停止后，应先查看排查资料；手动 Start 才重新尝试失败项，程序不会自动重新启动。

**实际保存位置**

```text
D:\VIPRPG-Rescue\uploaderjp-202611\
  files\<上传区>\<文件编号>\<原始文件名或可逆安全名称>
  source-pages\             原始 HTML 响应和请求来源记录
  queue.sqlite              SQLite 队列；WAL 文件必须一并保留
  settings.json             下载节流、容量阈值等运行设置
  status.json               每秒更新的工作进程状态
  supervisor.json           独立监控进程的心跳和退出判定
  launch.json               当前运行 ID、进程及日志位置
  stop.request              暂停请求
  logs\                     本轮 stdout/stderr、事件日志、代理日志
  reports\                  执行版本副本、告警、退出和验收证据
  private\                  独立代理配置及源站 cookie，禁止提交或分享
```

主入口为 `scripts/uploader_rescue.py`，PowerShell 文件提供方便调用。使用本机 Python 3.11 及已安装的 requests、beautifulsoup4；进度窗口使用 Python 自带 tkinter，数据队列使用 sqlite3。不需要浏览器、Next.js 开发服务器或本地翻译模型。

**来源与调度范围**

- 从 `catch/uploaderjp-rescue-20261023/seed-inventory.json` 初始化用户提供的 17 个整区入口及原有 626 组历史文件编号候选。新发现的文件会增加队列总数，初始数量不是全库规模。
- 先列出一页，再执行下载；每处理约 8 个文件穿插下一次目录发现。分页按来源真实“次へ”链接扩展，并按分页深度和用户提供顺序轮转。已明确列出的文件优先于历史静态候选。
- 用户提供的 17 个目录是当前自动整区范围。其余候选上传区尚需按来源关系确认用途，再加入整区入口；不能将 143 个候选入口宣称为已完整抓取。
- 保存原包、补丁、文本链接清单、图片等实际列出的文件。只解析下载所需的编号、文件名、大小、时间、表单与链接，不主动查看作品内容，不执行下载文件。
- 确认页通过真实表单处理；未提供密码、完整性校验失败等需要人工处理的项目保留为 `needs_input`，立即中断整个下载流程并告警。可恢复的连接失败、超时、指定的临时 HTTP 状态先对同一项重试，默认等待 10、30、90 秒，最多重试 3 次（连同初次共 4 次尝试）。仍失败则标记 `failed` 并中断，不会跳过后继续其他文件。

**独立日本出口与节流**

本机工作流使用 `127.0.0.1:17997` 的独立 Mihomo 代理，固定为已配置的日本下载节点。现有 Clash Party 的共享选择器保持原样。只在任务私有目录保存所需配置，控制接口仅监听本机并需要口令；口令不进入日志和仓库。

`private/proxy-control.json` 记录本机 Mihomo 程序位置及专用配置，Start 会检查并在需要时启动该专用代理。首次部署到另一台机器需要重新准备其私有代理配置，不能直接复制本机认证资料到仓库。

全工作流仅一条文件下载流，源站请求间隔至少 2 秒，遵守页面给出的下载倒计时。429／503 等临时响应记录为重试，遵守 Retry-After／退避等待，不弹错误窗口。等待和重试完成前不处理其他文件；重试耗尽才计为真正错误并中断。

**文件完整性与断点**

- 先写 `payload.part`，记录 HTTP 精确长度、ETag／Last-Modified、原始文件名及目的路径；传输结束后检查实际字节数，再原子改名。
- 原始文件名及路径映射保存在每个文件目录的 `transfer.json` 中。Windows 禁止的文件名字符会安全替换；不同编号不共用文件路径，不覆盖已有文件。
- 已有部分文件只在有版本验证器时续传，携带 Range 和 If-Range。响应必须是正确的 206、匹配的 Content-Range、总长度和版本验证器；验证器变化或缺失时保留旧部分文件，下次从头下载。
- 服务器忽略 Range 返回 200 时保留旧断点，完整重下，绝不直接追加。已完整落盘、尚未完成登记的文件可继续校验登记，无需发出越界 Range 请求。
- 识别 HTML 错误页冒充下载包。对于来源本就提供的 HTML 文件，以实际文件元数据区分。
- ZIP 先检查目录，再对未加密、展开总量不超过 8 GiB 的压缩包读取全部条目以核对 CRC；不将内容展开到磁盘或查看具体文本／画面。加密 ZIP、超大展开量 ZIP 的验证范围单独记录。ZIP 损坏时原始字节保留并告警。
- 不额外计算 SHA-256。

**出错告警与进程监督**

下载、监督和进度窗口为独立进程。监督进程持有其启动的真实工作进程句柄，检查每秒心跳并记录退出码，不用遗留 PID 文件或超时观察代替存活判断。心跳超过 20 秒不更新时停止本轮：先请求安全暂停，等待原工作进程退出；超过有界等待仍未退出才终止该进程并保存现场，绝不另起一个下载进程与其重叠。

重试过程写为 `retry`，最终恢复写为 `retry_recovered`，不计错误、不弹窗，也不重置连续成功数。只有重试耗尽、不可重试的 HTTP 错误、校验失败、需要人工处理或进程异常才写 `error`，立即中断下载。后面的文件不会被继续请求。

真正错误只显示一个独立的置顶告警窗口，提示下载已中断并给出排查资料目录。告警以当前队列状态核对是否仍需处理，不在关闭后补弹已经恢复的历史错误；同一工作流由进程锁保证不叠加告警窗口。手动处理并恢复任务后，已经解决的提示自动撤销。窗口与进程的退出需实际核验，不能把发送关闭消息成功当成已经关闭。

工作进程突然退出，即使未写最终状态、进度窗口未打开，监督进程也会告警并保留退出报告。意外退出后需人工查看原因再 Start，不盲目自动重启。

监督进程自身无法启动或运行失败，也会走独立告警路径。运行时 `private/`、`logs/` 和 `reports/` 保留诊断证据，不能只因重新启动后继续传输就断言根因已经修复。

真正错误的排查资料位于 `reports/incidents/<时间与编号>/`：异常堆栈、失败项与尝试次数、一致性 SQLite 快照及 quick_check 结果、状态和启动记录、相关日志尾部、不含认证内容的代理上下文。失败 HTTP 响应另保留原始状态、响应头和最多 64 KiB 原始响应体，放在 `private/response-failures/`；完整文件和 `.part` 留在原位置。资料中明确记录响应保存失败等诊断缺口。

**容量边界**

默认最多占用 80 GiB 文件暂存空间，并为 D 盘至少保留 80 GiB 空闲。开始每个文件前检查容量，传输途中持续检查空闲底线。触及容量边界会停止本轮并前台告警，保留队列及未完成文件；不会把所有待下载文件逐一误标记成容量失败。

更改运行参数在 `settings.json` 中进行，下一次 Start 生效。当前阶段没有上传或回验后清理行为，因此达到容量上限后需要后续安排存储或百度转存。

**验证与完成判据**

连续成功达到 50 时自动写入 `reports/milestone-50-<run_id>.json`，包含 50 个真实文件完成事件，下载继续进行。验收还需独立核对数据库事件区间无错误、实际文件路径和字节数、执行版本、实时面板及监督进程存活；不能只凭数字或里程碑文件本身宣布完成。
